# 기획안 대조: 빠진 기능과 달라진 점 (proposal-gaps.md)

> 제출한 기획안(본문 3쪽)과 별첨(1~9)을 `CLAUDE.md`·저장소 구현과 대조한 결과다. 기준일 2026-10-08.
> 기획안이 기준 문서이고, 이 파일은 "기획안에는 있는데 구현 문서나 코드에 없는 것"을 모은 점검표다.
> 항목을 반영하면 `CLAUDE.md` 의 '범위'·'기능' 표와 이 파일을 함께 고친다.

## 3. 기획안에서 '하지 않는다'로 정한 것 (재확인)

- 환승 경로 안내(별첨 4 ⑦ "환승 경로는 시범 범위 밖"), 미탑승 인원·필요 증차 대수 추정(별첨 9), 학습 모델 재학습(본문 기대효과 "재학습 없이 확대").
- 화면은 '탑승 보장'이 아니라 '무좌석 위험'(별첨 6).
- 개인정보: 위치·이름·전화번호를 받지 않는다. 시민 시험은 동의서와 익명 번호(별첨 3).

## 4. 담당별 의존 관계

| 구분 | 항목 |
|---|---|
| BE·FE 만으로 가능 | G2 리포트 집계(라벨 확장 포함, 해석은 모델링), G3 입력 수단, G4 시험 모드 화면 틀, G7 집계, G9, G10, G11, 알림 화면 강조 |
| 팀 결정이 먼저 | G5 알림 방식, G6 시간표 담당, 하차 정류장·허용 보행시간, 선행시간 기준, LLM 서비스·키, 지도 외부 호출 예외 |
| 모델링 산출물이 먼저 | G1 어림셈 기준선(STCIS 자료), 사례 검색 결과에 기대는 G8, 공개 판정(보정 오차·재현율·정밀도·Brier) |

## 5. 시기 제안

| 시기 | 할 일 |
|---|---|
| 2차 제출(10/15)까지 | 사례 검색 연결, LLM 조건 변환·설명·검사기(G10 포함), 리포트 1차(G2: 덕현초교 30분대, 가능하면 노선 전체), 첫 실측값, STCIS 승하차 자료 확보 시작(G1) |
